# Android — one-time setup (Windows dev machine)

Do this once before any Android build is possible. `tools/release.js`
refuses the Android target until step 6 has produced
`src-tauri/gen/android/app`.

**Nothing below has been verified from the Cowork sandbox** — it has no
Android SDK, no JDK, no Rust toolchain (`CLAUDE.md` §4). The first real
test is on this machine. If `tauri android init` or the first build hits a
snag, it gets its own follow-up pass, the same way the desktop Tauri
scaffold needed two local rounds (`HISTORY.md` 0.2.11-0.2.16).

## 1. Android Studio

Install Android Studio (https://developer.android.com/studio). It bundles
the SDK Manager used in step 2 and a JDK that can serve for step 3.

## 2. SDK components

Android Studio → Settings → Languages & Frameworks → Android SDK:

- **SDK Platforms** tab: at least one Android SDK Platform (the current
  stable API level is fine).
- **SDK Tools** tab (tick "Show Package Details"): the matching
  **Android SDK Build-Tools**, **Android SDK Platform-Tools**,
  **Android SDK Command-line Tools**, and **NDK (Side by side)**. Note the
  NDK version number — its path is needed in step 4.

## 3. JDK

JDK 17-21. Install a standalone one (Adoptium Temurin) rather than relying
on Android Studio's bundled JBR — on at least one real machine that bundled
JBR turned out to be Java 25 (confirmed via `gradlew --version`'s "Launcher
JVM" line), which Gradle 8.14.3 can't run its own build scripts on
("Unsupported class file major version 69", §6a). Android Studio's bundled
runtime version isn't pinned to what Gradle supports and can change on an
IDE update, so don't assume it's safe without checking — `<jdk path>\bin\
java.exe -version` directly (not just whatever `java` resolves to on
`PATH`, which may be a different install entirely) before relying on it.

## 4. Environment variables

System (or user) environment variables — Settings → System → About →
Advanced system settings → Environment Variables. Adjust paths to the
actual install locations:

| Variable       | Typical value                                                        |
|----------------|----------------------------------------------------------------------|
| `JAVA_HOME`    | `C:\Program Files\Android\Android Studio\jbr`                        |
| `ANDROID_HOME` | `C:\Users\<you>\AppData\Local\Android\Sdk`                           |
| `NDK_HOME`     | `C:\Users\<you>\AppData\Local\Android\Sdk\ndk\<version from step 2>` |

(`ANDROID_SDK_ROOT` is the older name for `ANDROID_HOME`; setting both to
the same path is harmless.) Also append to `Path`:
`%ANDROID_HOME%\platform-tools` (for `adb`). Open a **new** terminal
afterwards — existing ones won't see the change.

## 5. Rust Android targets

The desktop build only needed the host target. Android needs the four
Android ones:

```
rustup target add aarch64-linux-android armv7-linux-androideabi i686-linux-android x86_64-linux-android
```

## 6. Initialize the Android project

From the VKDex project root (the folder with the root `package.json`):

```
npx tauri android init
```

Generates `src-tauri/gen/android/` (gitignored — regenerable build
scaffolding, not source). This is the directory `tools/release.js` checks
for. Re-run it only if that folder is deleted.

## 6a. Gradle/JDK pin (needed if you have more than one JDK installed)

If Gradle fails with `Unsupported class file major version NN`, it picked up
the wrong JDK from `PATH`/`JAVA_HOME` resolution (Gradle 8.x can't run its
own build scripts on a JDK newer than what it was built against — e.g. it
can't run on a JDK 25 install even if the *app* build itself would be fine
on it). Fix: add a line to `src-tauri/gen/android/gradle.properties`
(forward slashes, even on Windows):

```properties
org.gradle.java.home=C:/Program Files/Eclipse Adoptium/jdk-21.0.12.101-hotspot
```

(adjust to wherever your actual JDK 17-21 lives — **verify its real version
with `<path>\bin\java.exe -version` first**, don't assume from the folder
name or `JAVA_HOME`/`PATH` alone; Android Studio's bundled `jbr` was the
first thing tried here and turned out to be Java 25, not a safe default).
**This file is regenerated by `tauri android init`** — re-add the line any
time you re-run step 6. For a fix that survives re-init, add the same line
to `%USERPROFILE%\.gradle\gradle.properties` instead (create the file/folder
if it doesn't exist) — applies to every Gradle project on the machine, not
just this one, which is fine on a single-project dev box but worth knowing
if you ever build other Android projects here with different JDK needs.

## 6b. Expected noise: Kotlin daemon falls back mid-build

Confirmed harmless (first successful build, 2026-09-05): partway through
you'll likely see `Failed to compile with Kotlin daemon` with a stack trace
ending in `this and base files have different roots: C:\Users\...\.cargo\
registry\...  and E:\Claude\Projects\VKDex\src-tauri\gen\android`. This is
the Kotlin incremental compiler's path-relativizing logic choking on two
different drive letters (project on `E:`, `cargo`'s registry cache on `C:`)
— not a real failure. Gradle immediately prints `Using fallback strategy:
Compile without Kotlin daemon` and finishes the build without it (just
slightly slower, no daemon reuse across the per-arch passes). No action
needed; if you want to get rid of the warning entirely, the whole project
(or at least a symlink to `%USERPROFILE%\.cargo`) would need to live on the
same drive as `%USERPROFILE%` — not worth the disruption for a cosmetic
warning.

## 7. Build

```
npm run build:android        # = tauri android build --debug
node tools/release.js        # menu: 1 (Android) / 2 (Windows) / 3 (Both)
```

The debug build is signed with Gradle's auto-generated debug keystore
(`%USERPROFILE%\.android\debug.keystore`) — installable on a phone via
"Install unknown apps" for the browser/file manager used to open it, not
publishable to the Play Store. A release keystore is a separate future
decision (`TODO.md`); every later update of an installed app must be signed
with the same key, so it isn't something to generate casually.

Assumption to confirm on the first real run: `--debug` is the Tauri 2 CLI
flag for a debug build (it is in the CLI reference as of Tauri 2.x; `--apk`
can be added to skip the AAB Gradle also produces by default). The APK is
expected under `src-tauri/gen/android/app/build/outputs/apk/universal/
debug/` — `release.js` searches that whole `apk/` tree rather than
hardcoding the leaf, and lists what it found if no `.apk` turns up.
