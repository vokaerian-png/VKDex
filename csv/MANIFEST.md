# VKDex/csv/ — merged data source (PokeAPI clone + PokeDB), schema manifest

Generated by `node tools/csv_merge/merge.js` (2026-09-06) from
`temp/PokeAPI-master/data/v2/csv/` (185 files) and `temp/PokeDB-CSV/` (88 files).
149 files, 1,053,720 data rows, 73 MB, UTF-8, LF, RFC 4180 (`tools/csv_merge/csv_util.js`
parses every file back with 0 bad rows). `node tools/csv_merge/merge.js --verify`
re-runs the round-trip + 335 foreign-key checks + fixed row counts without rebuilding.

## Conventions

- **Keys are identifiers, not numeric ids.** Cross-table references use the lowercase-hyphen
  identifier of the target (`move`, `ability`, `item`, `type`, `pokemon`, `form`, `version`,
  `version_group`, `language`, ...). Species are keyed by National Dex number (`species`).
  Numeric PokeAPI `id`s are carried as a plain column where they exist (sprites in
  `src/data/sprites/` are named by `pokemon.id`); a blank `id` marks a PokeDB-only row.
- **Vocabulary is PokeAPI's** for every identifier (pokemon/form names, egg groups, growth
  rates, move targets, versions, currencies, languages). PokeDB values were mapped through
  `tools/csv_merge/form_aliases.csv` (1,476 PokeDB forms → PokeAPI `pokemon`+`form`),
  `item_aliases.csv` (PokeDB items → PokeAPI, 351 PokeDB-only kept under their own identifier)
  and static maps in `merge.js` (`LANGDB`, `CURRENCY_DB`, `TARGET_DB`, `EGG`, `GROWTH`).
- **`source` column** (`pokeapi` / `pokedb` / `both`) on the entity tables says which source(s)
  had the row. Absent = PokeAPI-derived table.
- **Names are wide**: one row per entity, `name_<lang>` columns (`name_en`, `name_ja`,
  `name_ja_roma`, `name_zh_hant`, ...), blank-tolerant union of both sources — a column exists
  only if some row has a value. `<lang>` = `languages.identifier` with `-` → `_`. Prose/flavor
  tables are long: one row per (entity, version[-group], `language`).
- **Versions**: `version_groups` + `versions` (PokeAPI shape). DLC keep PokeAPI's pseudo-versions
  (`the-isle-of-armor-sword`, `the-teal-mask-scarlet`, ...). PokeDB-fed tables carry
  `version_group` (always) and `version` (blank when PokeDB tagged a whole group).
  `version_groups.game` names the non-mainline split (`orre`, `legends_arceus`, `legends_za`,
  `champions`); rows for those groups live in `<table>_<game>.csv`, never in the mainline file.
  Japanese Red/Green/Blue (`red-green-japan`, `blue-japan`) are excluded everywhere (8,256
  learnset rows, 1,770 encounters, 110 machines, 3 versions dropped); PokeDB spin-off tags
  (`go`, `home`, `sleep`, `stadium`, `stadium-2`, `dream`, `green`...) are dropped too —
  every dropped row is counted in `tools/csv_merge/reports/merge/dropped_rows.csv`.
- **Conflict policy**: PokeAPI is the base wherever it has a value; PokeDB fills blank cells,
  missing rows (where the table's grain allows it — see per-table notes) and whole missing
  tables. ~130 species-level cells were hand-adjudicated against Bulbapedia / official sites
  (`tools/csv_merge/species_field_overrides.csv`: dex, field, both values, chosen value +
  source, reason). Every other disagreement is logged with the chosen value in
  `tools/csv_merge/reports/merge/conflicts_<table>.csv` (key, column, pokeapi, pokedb, chosen).
- Booleans are `1`/`0`. Blank = unknown / not applicable. Heights in m, weights in kg.

## Known gaps and limitations

- **Base experience Gen 1-4**: absent from both sources (only Gen 5-6 and Gen 7+ eras exist).
- **Base friendship Gen 1-2**: no per-species table in either source.
- **SV DLC encounters** are not split into Teal Mask / Indigo Disk pseudo-versions (no area→DLC data). SwSh DLC is (A's pseudo-versions).
- **ORAS encounters**: A has only 302 rows; B's 1,393 ORAS rows were not merged because A "has" the version (see the encounter rule above). Flip `POKEDB_ENC_FILES` in `merge.js` to add an `encounters_omega_ruby_alpha_sapphire.csv` if wanted.
- **Legends: Z-A** has no learnsets or encounters in either source; only TMs (`machines_legends_za.csv`), species/item flavor, items, prices, acquisitions, pockets. Z-A catch-rate changes (Bulbapedia: Zygarde 3→255, catch-3 legendaries →20/45, Kleavor 15→20) are in neither source and were not invented.
- **Legends: Arceus** learnsets (A) and encounters (B) are complete; B's LA-era catch rates for the 6 Hisui species turned out to be the *current* mainline values (Bulbapedia) — A's were wrong and are overridden in `species.csv`, so there is no separate LA catch-rate file.
- **Max/G-Max/Z-move damage class**: Z-moves `vary`; Max Moves keep A's `physical`/`special`; G-Max moves (B-only) `vary`.
- **Item `introduced_generation`** is A's earliest `item_game_indices` generation, which is a veekun index quirk in a few places; the 17 known cases are fixed, others may exist (B's column is itself wrong for Poké/Great/Ultra Ball = 8, so it could not simply win).
- **PokeDB presentation columns** (CDN image/audio URLs, `*_html` twins of `*_markup`, leaflet polygons, box art, game ratings, sprites, cries, type icons, region artwork), its `games`/platform catalogue, `pokedex_groups` navigation, markup evolution/form-change grids, `item_evolutions` (derivable from `pokemon_evolution`), `item_spin_off_datas` and Mystery Dungeon abilities were dropped. PokeAPI's `conquest_*` (31 tables), `pokemon_game_indices`, `type_game_indices` and `*_flavor_summaries` (empty) were dropped.
- `pokemon_dex_numbers` is species-grain (A); B's form-grain dex numbers (`lumiose_mega` list) were not carried.
- B forms with no A counterpart other than the 4 "Activated" rows were folded onto A rows (`raticate-totem`→`raticate`, `unfezant-female`→`unfezant`); see `form_aliases.csv` `how` column.

## Regenerating

`node tools/csv_merge/merge.js` rebuilds everything in ~35 s (Node 22, no dependencies), rewrites
`tools/csv_merge/species_field_overrides.csv`, `form_aliases.csv`, `item_aliases.csv` and
`tools/csv_merge/reports/merge/` (`conflicts_<table>.csv`, `dropped_rows.csv`, `output_files.csv`,
`fk_spec.json`), then verifies. Hand adjudications live in `merge.js` (`SPECIES_OVERRIDES`,
`FORM_HAND`, `ITEM_HAND`, `ITEM_GEN_FIX`, `EV_FROM_POKEDB`, `CURRENCY_DB`). An unlisted
species-level conflict is a hard error, so a source refresh cannot silently change a hand-fixed cell.
